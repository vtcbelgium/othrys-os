## Mission

Turn stocked rooms into evidence-bearing hunts. This wave concentrates on a market pattern that strongly matches machinery OTHRYS is already building: AI agents are spreading, but enterprises still need better proof, cost attribution, governance, routing and outcome measurement.

Hyperion therefore hunts the intersection:

`MORE AGENTS + MORE SPEND + MORE AUTONOMY -> GREATER NEED FOR PROOF + COST CONTROL + GOVERNANCE`

This is not permission to build every candidate. It is a ranked research queue.

## External signal snapshot

September 2026 research indicates:

- AI evaluation/observability is recognized as a distinct enterprise category because nondeterministic agent systems require repeatable reliability measurement.
- Agentic coding adoption is broad and competition is intense; the opportunity for OTHRYS is therefore less likely to be "another coding agent" and more likely to sit above/between agents: qualification, evidence, routing, governance and economics.
- Inference and agent usage create persistent operating costs, increasing the value of cost attribution, routing and optimization.
- Enterprise AI is moving from assistance toward delegated execution, increasing the importance of trusted control planes and outcome evidence.

External research is directional evidence only. Hyperion must reproduce important claims with OTHRYS-owned experiments before treating them as product proof.

## H001 — AGENT PROOF PACK / EVIDENCE GATE

### Buyer problem
Teams can observe traces and test outputs yet still struggle to answer the executive question: **did the agent actually complete the intended job correctly, safely and reproducibly?**

### Smallest sellable-later slice
A repository/workflow audit that produces:
- critical agent actions;
- claimed outcomes;
- required evidence;
- missing evidence;
- false-success risks;
- recommended receipt schema;
- gate policy;
- sample verification tests.

### Product ladder
`AUDIT -> RECEIPT SCHEMA -> CLI -> CI GATE -> HOSTED EVIDENCE LEDGER -> ENTERPRISE CONTROL PLANE`

### OTHRYS reuse
Evidence Gate, execution receipts, Themis, Talos, incident ledger, test harnesses, Mnem provenance.

### Proof mission
Run the same five OTHRYS tasks under two conditions: self-reported completion versus receipt-required completion. Count false positives, unverifiable claims, added latency and verification cost.

### Kill condition
If receipts add bureaucracy without materially improving detection of false success, narrow or kill.

## H002 — AI SPEND & OUTCOME OPTIMIZER

### Buyer problem
Token/API/cloud spend is easy to count; **cost per verified useful outcome** is much harder and much more valuable.

### Hyperion thesis
Do not build another generic token dashboard. Build the bridge:

`COST -> TASK -> MODEL/AGENT -> ATTEMPTS -> FAILURES -> RECOVERY -> VERIFIED OUTCOME`

### Outputs
- cost per successful task;
- cost per failed task;
- recovery tax;
- expensive-model overuse;
- cheap-model false economy;
- routing recommendations;
- provider concentration risk;
- local-vs-cloud break-even candidates;
- cost anomalies;
- monthly avoidable-spend estimate.

### Revenue routes later
Audit, monitoring subscription, API, enterprise FinOps integration, procurement report, shared-savings model only after contract/legal research.

### OTHRYS reuse
Switchyard/provider router, Tool Olympics, execution receipts, Cronos telemetry, local model tests, Prometheus vendor watch.

### Proof mission
Instrument 100 controlled OTHRYS tasks and calculate whether routing by verified-outcome economics produces a materially different recommendation from routing by token price alone.

### Moat
Longitudinal cost-to-outcome data rather than provider list prices.

# EVIDENCE QUEUE

## E-001 — False-success delta
Measure how often evidence receipts catch a task that an agent reported as complete but was not verifiably complete.

## E-002 — Cost-per-outcome delta
Compare model ranking by list/token cost against ranking by verified successful outcome.

## E-003 — Builder stability
Repeat the same benchmark set over time and measure ranking volatility/regression.

## E-004 — Repo readiness
Apply Repo-to-Agent Readiness Audit to OTHRYS itself and identify whether the audit reveals actionable blockers not already obvious.

## E-005 — Waste recovery
Identify avoidable AI spend in OTHRYS's own controlled workloads and verify whether proposed changes preserve outcome quality.

## E-006 — Failover reality
Force provider/model failure in a controlled environment and measure whether fallback actually preserves the task contract.

## E-007 — Incident reconstruction
Run a synthetic bad-agent event and test whether logs/receipts/state are sufficient to reconstruct and contain it.

No external sale is needed to run these. They make OTHRYS better even if every commercial hypothesis dies.

# HYPERION DECISION

Wave 001 concentrates research on **proof, cost and control**, because these opportunities have unusually strong alignment between:

- work OTHRYS needs for itself;
- measurable enterprise pain;
- reusable evidence/data;
- service-first routes;
- later software/API routes;
- recurring monitoring potential;
- defensibility through longitudinal controlled evidence.

The preferred pattern is:

`BUILD FOR OTHRYS -> MEASURE -> PROVE INTERNAL VALUE -> PACKAGE AS AUDIT -> REPEAT -> PRODUCTIZE ONLY AFTER REPEATED DEMAND`

Final Wave 001 law:

> **DO NOT COMPETE WITH EVERY AGENT. BECOME THE SYSTEM THAT KNOWS WHICH AGENT WORKED, WHAT IT COST, WHETHER IT CAN BE TRUSTED, AND WHEN IT STOPPED BEING THE RIGHT CHOICE.**
