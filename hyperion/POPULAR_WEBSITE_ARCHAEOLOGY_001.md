# HYPERION — POPULAR WEBSITE ARCHAEOLOGY 001

Date: 2026-09-08
Status: RESEARCH / IDEA STOCK, NOT BUILD AUTHORITY

## Mission

Study proven website/product patterns as evidence of jobs people repeatedly want done. Hyperion does not need OTHRYS to invent every category. A legitimate strategy is:

`PROVEN DEMAND -> STUDY THE JOB -> FIND FRICTION -> REIMPLEMENT INDEPENDENTLY -> MAKE IT FASTER / CLEARER / CHEAPER / MORE PRIVATE / MORE VERIFIED / MORE SPECIALIZED -> TEST`

We copy **problems and successful product mechanics**, not protected code, branding, content, proprietary datasets, deceptive lookalikes, or confusing trade dress.

## Market signal

The largest web properties remain dominated by fundamental repeated jobs: search, video/content consumption, social communication and AI assistance. This tells Hyperion that frequency and habit matter enormously, but these giant horizontal markets are not sensible direct targets for the OTHRYS factory.

The interesting layer is the long tail of narrower utilities and workflows around those jobs.

Current micro-product directories show active categories around analytics, automation, business intelligence, productivity, finance, legal/document workflows, HR/recruiting, monitoring, directories, advertising/content generation, exam preparation, APIs and vertical AI tools.

Public indie evidence also shows successful one-feature apps, developer utilities, APIs, directories, WordPress plugins, AI interfaces and automation products. Revenue claims in indie directories are often self-reported and must be treated as signals, not audited truth.

## The clone-better doctrine

Hyperion may ask of any popular product:
1. What exact job creates repeat visits?
2. What is annoying about the incumbent?
3. Which features are baggage?
4. Can the job be done in one screen?
5. Can sign-up be removed?
6. Can processing happen locally/private-by-default?
7. Can OTHRYS verify the output?
8. Can we make pricing simpler?
9. Can we target a neglected niche/version?
10. Can we make export/portability radically better?
11. Can we combine several adjacent tools without creating bloat?
12. Can the result become shareable/searchable?
13. Can a free version be genuinely complete while paid value comes from scale, history, automation, monitoring or teams?
14. Can the product run with near-zero human support?

Rule:
> DO NOT ASK WHAT HAS NEVER EXISTED. ALSO ASK WHAT MILLIONS OF PEOPLE ALREADY DO BADLY.

## Website families to mine

### 1. File transformation
Proven job families: PDF merge/compress/split/convert, image resize/compress/crop/convert, OCR, format conversion, archive tools.

OTHRYS angles:
- privacy-first browser processing
- batch jobs
- evidence that files were deleted/not retained
- automatic quality comparison
- workflow chaining
- smart compression target ('under 2 MB without ugly text')
- document Doctor before conversion

### 2. Calculators
Finance, percentage, time, work-hours, travel, pricing, SaaS metrics, tax estimators, unit conversion, hardware fit, API/model costs.

Lesson from current indie builders: building 50 calculators is easy; traffic and trust are not. Broad keywords face entrenched incumbents. Prefer specific pain queries and useful explanation/assumptions.

OTHRYS angles:
- calculator + explanation + scenario comparison
- live-source calculators where freshness matters
- calculators generated from observed search pain
- calculators that naturally lead to a deeper tool

### 3. Checkers / diagnostics
SEO checker, speed checker, SSL/DNS, broken links, schema, robots.txt, accessibility, AI readiness, repo health, dependency health, email/domain configuration.

This is especially strong for OTHRYS because verification is native to our architecture.

Pattern:
`INPUT -> FREE SCORE -> EVIDENCE -> FIX PATH -> MONITORING / DEEP REPORT`

### 4. Generators
QR/barcodes, invoices, signatures, schemas, metadata, policies/checklists, mock data, names, structured documents, social assets, diagrams.

Better angles:
- verified output
- domain-specific packs
- history/versioning
- batch generation
- export everywhere
- local/private generation

### 5. Developer utilities
JSON/YAML/XML formatters and converters, regex tools, cron builders, JWT inspection, API request builders, diff tools, mock-data generation, dependency/version checks, README/repo diagnostics, model/API cost estimators.

Developer users are attractive because self-service tolerance is high and OTHRYS can dogfood the products.

### 6. Directories / comparison engines
AI tools, APIs, SaaS stacks, jobs, grants, learning resources, hardware, models, plugins, travel/collector niches.

Better angle is not 'more listings'. It is verified freshness, independent scoring, historical changes, compatibility and evidence.

Potential Hyperion product:
`DIRECTORY + PROMETHEUS WATCH + TOOL OLYMPICS EVIDENCE + PRICE HISTORY + ALERTS`

### 7. Monitoring
Website uptime/change, competitor pricing, API/model pricing, dependencies, policy/terms changes, product availability, job/grant listings, domain/SSL expiration.

Monitoring creates natural recurring value because the product continues doing work after the user leaves.

### 8. Summarize / transform knowledge
Transcript -> notes, meeting -> actions, document -> structured data, email -> tasks, lesson -> flashcards, long report -> decision brief.

Do not compete as generic 'AI summarizer'. Target a named workflow with deterministic structure and verification.

### 9. Search / retrieval niches
Search is the web's strongest repeated behavior. OTHRYS should not clone Google. It can create narrow search engines where curation/provenance/freshness matters: documentation, grants, tools, model pricing, public datasets, collections, heritage, learning material, product manuals.

### 10. Marketplaces
Templates, workflows, prompts, agents, datasets, components, niche digital assets.

OTHRYS angle: VERIFIED marketplace. Every asset carries compatibility, tests, provenance, cost envelope and last-verified date.

### 11. Resume / career / job utilities
CV checks, ATS formatting, job-match explanation, application tracker, interview preparation, salary comparison.

Strong demand but crowded. Better through evidence and workflow integration rather than generic generation.

### 12. Education / exam tools
Practice questions, flashcards, study plans, transcript processing, gap detection, spaced repetition, exam simulators.

Study Buddy provides dogfood and reusable infrastructure. Vertical course/exam packs may outperform a generic education chatbot.

### 13. Content/image production
Background removal, resize, ad creatives, thumbnails, screenshots, social formatting, image enhancement.

Crowded, but specific batch workflows and API/pay-per-run models remain interesting.

### 14. Personal organization
Habit, journaling, expenses, household budgets, reminders, personal knowledge, document organization.

Value increases with accumulated history: memory itself becomes an upgrade trigger.

### 15. Business micro-operations
Invoice extraction, lead routing, appointment handling, inbox triage, recurring reports, spreadsheet cleanup, competitor monitoring, customer-support triage.

Prefer products where the business can self-connect and see value without a call.

## Search-site factory lesson

A recent indie case study describes publishing 50+ calculator/guide pages and discovering that technical SEO alone did not create traffic; broad terms were dominated by established domains. Hyperion should encode this as a factory constraint:

> GENERATION IS CHEAP. TRUST, DISTRIBUTION AND SPECIFIC INTENT ARE THE SCARCE PARTS.

Therefore automatic website production should not become programmatic junk SEO. Candidate pages need a real job, unique utility, useful explanation/evidence and a distribution hypothesis.

## Pattern portfolio

The factory should deliberately mix:
- SEARCH BAIT WITH REAL UTILITY — calculators/checkers/converters
- HABIT — monitoring/history/personal memory
- TRANSACTION — pay-per-run transformations
- DEPENDENCY — workflow automation
- DATA MOAT — histories/benchmarks/directories
- ECOSYSTEM DISTRIBUTION — plugins/extensions/marketplaces
- SHAREABILITY — reports/scores/badges

A portfolio containing all seven has more evolutionary surface than 100 near-identical AI wrappers.

## New law

> PROVEN DEMAND IS NOT A REASON TO AVOID A MARKET. IT IS EVIDENCE THAT THE JOB MATTERS.

Competition is a filter, not a prohibition. Hyperion should prefer a crowded market with a clear neglected pain over an empty market nobody wants.

But:

> COPY THE JOB. STUDY THE MECHANICS. REIMPLEMENT INDEPENDENTLY. EARN THE RIGHT TO SAY BETTER.
