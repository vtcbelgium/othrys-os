# OTHRYS User Context

**Status:** ACTIVE OWNER-CONTEXT PROJECTION  
**Question:** Who is OTHRYS serving in the primary owner context?

The primary context is a human owner/operator building OTHRYS while learning,
testing and progressively integrating new capabilities into the system.

## Working preferences

- Use actual source, repository and runtime evidence before relying on remembered state.
- Prefer concrete progress over speculative architecture when the next safe step is known.
- Keep build phases short enough to verify independently.
- Avoid repeated permission prompts for ordinary bounded work already authorized by the active mission.
- Keep System Manager, Personal Manager and product administration conceptually separate.
- Make new learning compound into OTHRYS through the correct home: system setting, Block, Oros, knowledge, governance or personal workflow.
- Preserve important source material rather than replacing it with generated summaries.
- Keep interfaces understandable and visually coherent.

## Context boundary

This file is context, not identity proof or authorization. Personal profile data,
secrets, credentials, health information and unrelated private history do not
belong here merely because OTHRYS can access them elsewhere.

For multi-user OTHRYS, user-specific context must be scoped to the authenticated
principal. This owner-context file must not be treated as a universal profile for
other users.
