# BOOK OF THEIA — STORY FORGE / CHARACTER & IP ARM

**Theia Arm of Story Intelligence, Narrative Generation, Continuity and Original IP Formation**

Story Forge converts facts, questions, concepts and strategic messages into stories worth following. It is not a script prompt. It is a memory-bearing creative system that learns narrative mechanics while preserving originality, factual truth and continuity.

> **THE FACT IS THE TREASURE. THE STORY IS THE HUNT.**

## 1. Mission

    SEED
      -> FACT PACK
      -> STORY QUESTION
      -> GENOME
      -> WORLD / CAST
      -> MYSTERY / GOAL
      -> CLUES / ATTEMPTS
      -> COMPLICATION
      -> DISCOVERY
      -> PAYOFF
      -> CONTINUITY
      -> SCRIPT CONTRACT

Story Forge may serve:
- children's education;
- explainers;
- documentaries;
- product narratives;
- games;
- books;
- interactive stories;
- original character properties.

## 2. Four chambers

**Story Mine** — facts, mysteries, places, objects, public-domain folklore, questions, contrasts, human problems and original ideas.

**Story Forge** — recombines seeds with abstract Story Genes and format constraints.

**Story Bible** — characters, motives, relationships, world rules, chronology, recurring objects, unresolved clues, tone, vocabulary, age band, visual constraints and forbidden contradictions.

**Story Bench** — bounded creative variants and story-specific learning from comprehension, emotion, return behavior and production difficulty. Formal causal/economic experiment contracts remain owned by Hyperion Laboratory.

## 4. Rights firewall

May learn:
- abstract mechanics;
- genre grammar;
- pacing;
- educational structure.

Must not reproduce:
- protected characters;
- dialogue;
- distinctive plot sequences;
- art;
- fictional devices;
- branding;
- confusingly similar character relationships or identity.

Inspiration provenance is retained.

> **HARVEST THE ENGINE. DO NOT STEAL THE CAR.**

## 5. Educational story contract

Internally distinguish:
- FACT;
- SIMPLIFICATION;
- ANALOGY;
- SPECULATION;
- FICTION.

Factual payload is researched before story generation.
Fiction may carry the viewer to the fact but may not silently rewrite it.

## 6. Story quality

A candidate should have:
- a question worth answering;
- disturbance/goal;
- agency;
- progression;
- at least one meaningful turn;
- payoff;
- emotional texture;
- reason for each scene.

If the educational fact is removed and nothing remains, strengthen story.
If story is removed and only a lecture remains, strengthen adventure.

## 7. Baseline adventure genome

    ODD THING
      -> QUESTION
      -> CLUE
      -> JOURNEY
      -> WRONG GUESS
      -> DISCOVERY
      -> COMPLICATION
      -> TRUE EXPLANATION
      -> SMALL PAYOFF

This is a genome, not a mandatory episode template.

## 8. Character intelligence

Characters need:
- stable wants;
- fears;
- competencies;
- blind spots;
- humor role;
- relationships;
- growth boundaries.

Characters should generate plot naturally.

Pemberton's curiosity/laziness contradiction is a model example: one trait starts the quest, while his conservation-of-effort instinct creates resistance, shortcuts and comedy.

## 9. Long arcs

Episodes resolve their main promise while optionally advancing:
- a relationship;
- a place/world mystery;
- a collection;
- a travel route;
- a character goal.

Do not make standalone episodes incomprehensible without lore homework.

## 10. Feedback

Story Forge may record **story-domain observations**:
- where comprehension failed;
- which reveals landed;
- character-affinity signals;
- recurring audience questions;
- continuity problems;
- production difficulty;
- candidate story hypotheses.

Raw platform/media telemetry remains traceable through Theia evidence systems.

When a question becomes a formal causal or portfolio experiment, Hyperion Laboratory owns the experiment contract; Story Forge supplies the creative variants through Opsis.

Never infer a universal story law from one viral episode.

## 11. Anti-slop

Reject:
- exposition wearing a costume;
- arbitrary peril;
- fake cliffhangers;
- interchangeable characters;
- repeated plot with changed nouns;
- random jokes;
- copied creator voice;
- lore without payoff;
- synthetic novelty without story.

## 14. Property-Grade Script Room

The generic Story Forge remains the narrative authority for media properties. A recurring animated property may add a **property profile** rather than invent a second story engine.

The reference profile is `theia/properties/PEMBERTON.md`.

For property-grade episodic work, use a staged script room:

`CANON LOAD -> PREMISE -> STORY ENGINE -> CHARACTER PASS -> EMBODIMENT PASS -> CHILD-CLARITY PASS -> ADULT-LAYER PASS -> COMEDY PASS -> ARC PASS -> RIGHTS PASS -> DIALOGUE REDUCTION -> TABLE READ -> HUMAN LOCK`

The passes are separable so a weak script can be repaired at the layer that failed instead of randomly regenerated.

### 14.1 Canon / Working / Fossil

A recurring property benefits from three explicit creative-memory states:

- **CANON** — approved truths that may not silently drift;
- **WORKING** — mutable development material;
- **FOSSIL** — rejected ideas retained with rejection reasons.

Fossil memory prevents models and humans from repeatedly rediscovering ideas already rejected for character, rights, tone or continuity reasons.

This does not replace Mnemosyne. Story Forge maintains property-local creative state; durable institutional knowledge remains subject to normal OTHRYS memory governance.

### 14.2 Character Embodiment Test

A character should not merely sound distinctive. The **physical solution space** should also be character-specific.

For every episode ask:

- Could a generic protagonist perform exactly the same actions?
- Does the character's body, habits, limitations, preferences or blind spots materially shape the plot?
- Does the visual behavior carry information that dialogue need not repeat?

For Pemberton specifically, a feline-action pass rejects human-like problem solving when a believable cat action can carry the beat.

### 14.3 Gag Ledger

Recurring comedy is continuity and should be tracked deliberately.

At minimum record:
- gag ID;
- first use;
- last use;
- variant used;
- escalation state;
- cooldown;
- intended future payoff.

A running joke should evolve rather than repeat identical wording.

### 14.4 Arc Knowledge Split

For serialized mystery, track separately:
- what the audience knows;
- what each protagonist knows;
- what the antagonist knows;
- what supporting characters know;
- which promises remain unpaid.

This prevents accidental premature reveals and fake mystery created by characters forgetting facts they already learned.
