# OTHRYS OS Maximization Audit — 2026-08-29

**Mission:** V2-010L
**Method:** current V2 first, then legacy OTHRYS proof stock, then targeted external comparison.
**Goal:** maximize verified useful work per metabolic cost without multiplying authority or complexity faster than capability.

## Thesis
OTHRYS OS is still small enough to optimize at the architectural level. Current measured implementation is roughly: OS substrate 2.6k lines, Mycelium 1k, Hephaestus 300, Talos 570, Trust Canal 380, Factory 700, Command Deck 2.1k. The old Mycelium organism was ~32.7k lines. Therefore the correct move is not resurrection; it is selective re-admission of proven algorithms into the smaller V2 control/evidence spine.

## Current Ferrari laws
1. Remove duplicate work before accelerating work.
2. Run at the measured throughput knee, not at hardware redline.
3. Pack for locality/headroom; spread for failure diversity and alternative candidates.
4. Independent verification is intentionally duplicate computation and must never be anastomosed.
5. Projects express portable optimization intent; nodes expose measured capacity; Mycelium maps one to the other.
6. Hephaestus may multiply isolated hands, never shared-path writers or authority.
7. Talos proof remains external to producer success.
8. Derived/adaptive state may change preference, never law.
## Proven 010L gains
- Multichannel Mycelium: bounded PACK/SPREAD/STRICT_PACK/STRICT_SPREAD, cumulative capacity, saturation-aware score, width <=8, no launch authority.
- Real network: Legion↔T590 wired ~0–1 ms RTT and ~116 MB/s (~930 Mbit/s) with a sane client.
- Parallel full-runtime verification reduced wall time by ~45% versus sequential execution.
- Measured Node test knees: Legion ~16-way; T590 ~4-way. More parallelism gave negligible or negative return.
- Multi-hand Hephaestus: <=3 isolated hands, only disjoint slices or alternative candidates; real disposable worktree drill clean.
- WorkKey v1: deterministic operation identity; PURE / ENVIRONMENT_BOUND / TIME_BOUND / NONDETERMINISTIC; explicit nonce for nondeterministic work.
- Anastomosis planner v1: 100,000 equivalent shareable Claims -> 1 producer plan in ~69 ms; independent verifier Claims remain independent.
- Project optimization phenotype: six finite portable profiles; no node identities, authority, capability or model grants.
- Test scratch retraction: current TC/Heph/gate/Factory leak sources now produce zero net temp growth in focused proof.

## Per-project execution phenotypes
- **MINIMAL:** single lane, smallest footprint; simple utilities/extensions or fragile stateful work.
- **INTERACTIVE:** low-latency PACK bias, <=2 channels; UI/API loops where response time matters more than throughput.
- **BALANCED:** AUTO placement, <=4 channels; default software Oros.
- **BATCH:** wide safe PACK, <=8 channels and <=3 isolated Heph hands; import/index/report/build campaigns.
- **VERIFICATION_HEAVY:** SPREAD bias and verifier fan-out 2; OTHRYS OS/control/security/certification work.
- **GPU_HEAVY:** narrow PACK; preserve scarce GPU/VRAM and send CPU verification/background work elsewhere.

Project policy must stay portable. Node-specific knees, temperatures, queue depths, GPU pressure and network measurements remain derived local evidence.

## University / research-grade demonstration target
A compelling OTHRYS OS demo is not a giant agent swarm. It is a small heterogeneous autonomous-computing substrate that can prove these properties live:
1. Same project request produces a deterministic WorkKey.
2. Equivalent safe Claims fuse before execution; assurance Claims explicitly refuse fusion.
3. Project phenotype changes placement policy without changing authority.
4. Legion/T590 route selection reacts to real saturation and network evidence.
5. Two independent verifier lanes reduce proof wall time while preserving failure diversity.
6. Contention experiment demonstrates a non-maximal concurrency optimum and automatic contraction.
7. Isolated Heph hands race/disjoint-build in worktrees; Talos selects/merges only verified output.
8. Repeated successful route evidence changes disposable preference through Pareto+hysteresis, never route legality.
9. Crash/regrowth demo reconstructs from minimal trusted state rather than preserving the whole runtime body.

That is academically interesting because the optimization objective is explicit: **correct verified useful work / metabolic cost**, with authority and adaptive preference deliberately separated.

## Red zones worth probing, not blindly enabling
- delayed hedged execution for long-tail read-only tasks; never immediate duplicate AI work by default;
- adaptive concurrency from latency drift instead of static maxima;
- critical-path-first Factory execution plus WorkKey action cache;
- second qualified engineering builder before cross-node multi-Heph activation;
- local read-only artifact cache before any distributed CAS;
- per-project workload classes and SLOs before automatic fan-out;
- sclerotium clean-root regrowth before autonomy expansion.
