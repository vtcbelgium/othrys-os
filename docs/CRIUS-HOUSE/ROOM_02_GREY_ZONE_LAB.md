# ROOM 02 — GREY-ZONE LAB

Mission: investigate unconventional, indirect, underused, or structurally ambiguous money paths **without crossing into deception, evasion, rights violations, spam, dark patterns, fake reviews, hidden sponsorship, prohibited scraping, or unlawful conduct**.

`GREY` in CRIUS vocabulary means: commercially non-obvious, boundary-sensitive, or dependent on careful disclosure/terms — not illegal.

## Grey-zone principles

1. If revenue depends on hiding the commercial relationship, reject it.
2. If revenue depends on private/user data leaving its trust boundary without informed lawful basis, reject it.
3. If the platform/provider terms clearly forbid the behavior, reject it.
4. If a model works only because users misunderstand who is paying whom, reject it.
5. If a tactic is legal but would poison the long-term trust moat, score it as strategically toxic.
6. If legality depends on jurisdiction/status, mark `LEGAL_REVIEW_REQUIRED` rather than inventing permission.
7. Prefer asymmetries where OTHRYS creates value once and captures it several ways.

## High-interest patterns

### Free diagnostic -> paid cure
Give away a useful, honest diagnosis. Charge to implement the remedy.

Examples:
- Repo scan finds test debt -> paid repair package.
- AI stack scan finds 38% avoidable cost -> paid routing migration.
- SME automation scan finds repetitive work -> paid implementation.
- Agent safety scan finds uncontrolled tools -> paid guardrail deployment.

The free output must stand on its own. Do not intentionally cripple it to manufacture the sale.

### Free product -> commercial lead engine
A narrow tool can remain free because its users self-identify a high-value need.

Examples:
- legacy-health checker -> software rescue leads
- AI cost calculator -> optimization consulting leads
- GDPR/data-flow mapper -> compliance-tech implementation leads, without pretending to give legal advice
- migration readiness checker -> paid migration

### Sponsor pays, user remains free
A product can be useful to the user and valuable to a sponsor if the sponsor cannot buy the answer.

Examples:
- benchmark portal sponsored by infrastructure vendor
- educational tool sponsored by relevant employer/industry body
- open dataset sponsored by a vendor, with methodology/rankings independent

### Open-source wedge
Open-source a component that increases adoption while charging for scarce complements:
- hosting
- team governance
- audit logs
- enterprise SSO
- managed upgrades
- private connectors
- support/SLA
- policy packs
- certification

### Affiliate without becoming affiliate trash
Affiliate revenue is acceptable where:
- recommendation quality exists without commission;
- affiliate status is disclosed;
- ranking does not secretly depend on payout;
- non-affiliate alternatives remain eligible;
- price/value claims remain evidence-backed.

Strong candidates: learning tools, developer tools, hosting, books, hardware, marketplace listings, travel tools, collection marketplaces — only where program terms and disclosure rules permit.

### Shared savings
Instead of charging a fixed SaaS price, take a defined share of verified savings.

Possible use:
- AI provider cost optimization
- cloud/resource optimization
- redundant SaaS/tool cleanup
- support automation

Requires excellent baselines, attribution, contracts, and anti-gaming rules. Potentially strong B2B economics.

### Outcome-based pricing
Charge for verified result rather than access.

Examples:
- successful repo recovery
- validated migration
- qualified automation opportunity report
- tested bug fix batch

Avoid outcomes that depend heavily on factors OTHRYS cannot control.

### Free public benchmark -> paid private benchmark
Use public standardized tests as distribution and credibility. Sell private runs against a company's own stack/code/data under strict confidentiality.

### Public intelligence -> paid depth
Publish enough to create trust and search demand. Charge for:
- full dataset
- alerts
- history
- API
- custom watchlists
- organization-specific analysis
- faster cadence

Prometheus is ideal for this pattern.

### Tool directory -> qualified referral economy
Build a genuinely useful verified directory of AI/dev tools. Revenue possibilities:
- disclosed affiliate links
- clearly marked sponsored placement
- vendor verification fee
- enterprise shortlist service

Never sell the `best` badge.

### Certification / qualification
Make the evaluation itself valuable:
- Agent Driving Licence
- model capability certificate
- tool trust certificate
- connector compliance test

Potential revenue from test runs, continuous requalification, enterprise private packs, or API access. The standard must be independent from who pays.

### Data exhaust -> intelligence product
Controlled OTHRYS experiments may produce commercially valuable aggregate knowledge:
- which models fail which tasks
- repair success by strategy
- latency/cost trends
- provider regression histories
- tool qualification histories

Commercialize the **derived intelligence**, not secrets or user payloads.

### Dormant IP resurrection
Old scripts/components/templates may be worthless alone but valuable when:
- cleaned and packaged as a paid toolkit
- combined into a service
- licensed to a niche
- used as lead magnet
- bundled with implementation

### Product as proof-of-capability
A free product can act as a living portfolio that earns consulting, employment, partnerships, speaking, training, or contracts without charging the end user.

### White-label invisible engine
OTHRYS-powered capability can sit behind another brand. Revenue may be higher and support narrower than consumer SaaS.

### Reverse freemium
Charge organizations while keeping individuals/students free when organizations gain admin, governance, integration, reporting, or risk-control value.

### Procurement intelligence
Prometheus/Switchyard data could help organizations choose models/vendors. Possible paid reports, vendor-neutral RFP scoring, and renewal negotiation evidence. Must disclose conflicts and avoid kickback-driven rankings.

## Areas requiring explicit legal/terms investigation before use

- referral/affiliate disclosures by jurisdiction/platform
- automated comparison claims
- scraping/data reuse
- resale of third-party API output
- marketplace data usage
- generated training datasets based on third-party material
- user telemetry aggregation
- certification language and liability
- performance/outcome guarantees
- shared-savings contracting
- payment facilitation
- financial/investment recommendations
- employment/course/unemployment-benefit implications for operator income

## Grey-zone scoring

Score each candidate 0–5:

`VALUE_ASYMMETRY + USER_BENEFIT + REUSE + MARGIN + DISTRIBUTION + DEFENSIBILITY - TRUST_RISK - LEGAL_AMBIGUITY - PLATFORM_DEPENDENCE - SUPPORT_BURDEN`

Any idea with `TRUST_RISK >= 4` requires a redesign rather than enthusiasm.
