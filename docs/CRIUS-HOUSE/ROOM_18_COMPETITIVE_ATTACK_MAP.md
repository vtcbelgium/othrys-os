# ROOM 18 — COMPETITIVE ATTACK MAP

Mission: identify where OTHRYS can enter an existing market by being materially cheaper, more trustworthy, more automated, more local/private, or more evidence-driven.

## Attack lenses

### Price attack
Can OTHRYS deliver a comparable result at radically lower cost because automation removes human labor?

### Trust attack
Can OTHRYS win because incumbents provide opaque AI output while OTHRYS provides receipts, provenance, tests and explicit uncertainty?

### Simplicity attack
Can a bloated enterprise product be replaced for a small customer with one narrow workflow that works extremely well?

### Local/private attack
Can local models/self-hosting create privacy or cost advantages?

### Speed attack
Can OTHRYS deliver in minutes/hours what currently takes days?

### Integration attack
Can OTHRYS eliminate stitching together five separate tools?

### Data/history attack
Can OTHRYS's longitudinal benchmark/failure history create better decisions than static comparisons?

### Service-to-software attack
Can an expensive consultant deliverable be standardized and partially automated?

## Candidate incumbent categories to investigate

- code audit consultants
- legacy modernization consultancies
- AI cost management tools
- model routing platforms
- AI coding benchmark sites
- agent observability platforms
- developer documentation tools
- knowledge/handover tools
- AI governance/qualification tooling
- tutoring/study apps
- internal knowledge assistants
- workflow automation consultancies
- collector catalogue apps

## Attack packet

For each category record:
- incumbent price
- user complaints
- core must-have feature
- unnecessary complexity
- trust weaknesses
- switching friction
- OTHRYS reuse advantage
- smallest wedge
- distribution route
- reason not to enter

## Rule

Do not enter a market because it is large. Enter when OTHRYS has a credible wedge that can be proven.
