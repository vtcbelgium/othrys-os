# ROOM 11 — EXPERIMENT FOUNDRY

Mission: turn commercial ideas into cheap, falsifiable tests before they become roadmap work.

## Experiment contract

Every CRIUS experiment states:
- hypothesis
- target user/buyer
- value assumption
- cheapest valid test
- evidence required
- success threshold
- failure threshold
- cost ceiling
- time ceiling
- privacy/legal constraints
- what will NOT be built
- STOP condition
- next decision if pass
- next decision if fail

## Preferred experiment order

1. Search existing evidence.
2. Interview/observe actual pain where available.
3. Test demand without building full product.
4. Test willingness to engage.
5. Test willingness to pay only when financial gates permit real payment; otherwise use non-transactional interest signals.
6. Test delivery manually/semi-manually.
7. Automate repeated steps.
8. Build only after evidence justifies it.

## Experiment patterns

### Concierge test
Deliver the outcome manually with OTHRYS assistance before building automation.

### Wizard-of-Oz test
Present a simple front end while humans/OTHRYS manually execute behind it. Must not make deceptive claims about automation.

### Fake-door interest test
Show a future feature or plan and measure clicks/waitlist interest without charging or implying immediate availability.

### Report test
Generate a sample audit/benchmark/intelligence report and see whether target users find it valuable.

### Landing-page test
Explain the outcome, target user and package; measure qualified interest.

### Tiny-tool probe
Build the smallest useful single-purpose utility and measure organic discovery and repeat use.

### Private pilot
Use one real willing user/company to learn operational burden and value.

### Benchmark publication
Release original evidence and measure whether it attracts users, vendors, press, links, subscribers or enterprise questions.

### Price sensitivity research
Use interviews/surveys/scenario choices; avoid pretending payment is live when Course Mode forbids it.

### Manual service first
Sell later when allowed, but even while locked, simulate the delivery pipeline on owned/test material to learn actual effort and margins.

## Kill criteria

Kill or park when:
- target pain is weak
- acquisition is implausible
- value cannot be proved
- support burden dwarfs margin
- required rights cannot be obtained
- platform dependence is unacceptable
- product undermines trust
- OTHRYS has little reusable advantage
- experiment repeatedly fails

Failure is useful if recorded. A dead idea should make the next score smarter.
