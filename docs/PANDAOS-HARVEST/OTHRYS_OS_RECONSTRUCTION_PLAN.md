# OTHRYS OS — 8-Step Reconstruction Plan

**Locked:** 2026-08-27  
**North Star:** OTHRYS OS surface over the proven V2 motor.  
**Method:** reconstruct PandaOS to learn; expose existing OTHRYS stock before creating replacements.

## Governing laws
1. **COPY BEFORE CREATE** — study a solved interaction/mechanism before inventing one.
2. **EXPOSE BEFORE REBUILD** — V2 motor capability gets surfaced, not duplicated.
3. **PROVE BEFORE EXPAND** — Panda and OTHRYS earn larger scope only through evidence.
4. **ONE CONCEPT / ONE RECONSTRUCTION** — finish, verify and log before the next concept.
5. **CLAIM != EVIDENCE** — interrogate Panda, then test its answer against behavior.
6. **UI != AUTHORITY** — OTHRYS truth remains in canonical state, receipts, Trust Canal and independent verification.
7. **RECONSTRUCT, DON'T COUNTERFEIT** — copy useful principles/flows, never proprietary code/assets/branding.
8. **NORTH STAR TEST** — every addition must improve autonomous build, verify, operate, repair or maintain capability, or make that machinery materially easier to operate.

## Daily operating loop
`OBSERVE PANDA -> ASK PANDA -> TEST -> LOG -> INVENTORY V2 -> MAP -> RECONSTRUCT -> VERIFY -> RECEIPT -> COMPARE`

At every boundary record screenshots/observations, prompt, permissions, model/provider, state transition, artifact/evidence, failure/retry, cost/usage when visible, operator intervention, classification and next question.
## Step 1 — OS Shell / Information Architecture
**Reference:** Panda Projects, Work, Team, Skills, Knowledge, Apps, Integrations, Models, Settings.  
**OTHRYS mapping:** Oroi/Projects, Missions, Titans, Blocks, Mnemosyne, Engines/Apps, Switchyard, Mycelium/Settings.

First inventory existing V2 surfaces and contracts. Reconstruct only a thin OTHRYS OS shell that can expose real state progressively. Empty/placeholder areas must say NOT WIRED rather than simulate capability.

**Exit proof:** one coherent navigation/shell specification mapped to canonical V2 owners; no duplicated backend architecture.

## Step 2 — Work State / Mission Control
Reconstruct Panda's strongest observed mechanism first: durable objective/problem/scope/risks, slices/tasks, phase owner, execution mode, transition state, answered decisions and Progress surface.

Map authorization gates to Trust Canal and proof/evidence gates to Talos. Declare expected artifacts before execution where possible. Builder cannot certify itself.

**Exit proof:** one real bounded OTHRYS Mission can be represented end-to-end without inventing a second mission engine.

## Step 3 — Team + Skills / Titans + Blocks
Study persona activation, skill attachment and handoff UX. Keep the simplicity while preserving stronger OTHRYS semantics: Titans are domain authorities; admitted Blocks are proven capabilities, not prompt snippets.

**Exit proof:** UI can explain who owns work, why, which Blocks are admitted/used, and what is merely candidate stock.
## Step 4 — Knowledge / Atlas -> Mnemosyne
Do not build from screenshots alone. Enable/test Atlas only under controlled scope and budget. Study watched projects, local semantic search, proposed knowledge changes, maintenance, review queues, agent write access, export, provenance and procedure-to-skill discovery.

OTHRYS must retain stronger admission/provenance boundaries between conversation, Garden candidate, accepted knowledge and runtime authority.

**Exit proof:** Mnemosyne design delta says exactly what to reuse from current stock, what Panda pattern is worth harvesting and what is rejected.

## Step 5 — Models / Switchyard
Study Auto selection, capability-tier requests, connection selection, quota failover, persistence, local providers and visible usage/cost behavior.

Expose OTHRYS's stronger target: free/local-first where fit, health, capability, certification, cost, failover and evidence-aware routing. Panda routing is a reference, not authority.

**Exit proof:** one routing surface reflects real provider/node state and can explain a selection.

## Step 6 — Mycelium + Visual Computer Use
Expose Legion/T590 as first-class nodes: health, capability, load, role, current work and evidence. Then advance Visual Control separately through OBSERVE -> SUPERVISED -> AUTONOMOUS.

Do not build TeamViewer. Prefer AI-useful screenshots/state + accessibility/window metadata, explicit authority and independent post-action verification.

**Exit proof:** real node state visible in OTHRYS OS; visual control cannot silently escalate authority.
## Step 7 — Apps, Integrations, Engines + Factory
Study how Panda makes external capability feel native. Define OTHRYS distinction between atomic Blocks and large governed engines/subsystems such as browser/computer-use, ComfyUI, n8n, Git/GitHub and local AI.

Factory/Oroi consume capabilities through explicit contracts; integrations do not become hidden authority paths.

**Exit proof:** at least one real external engine is represented as a governed OTHRYS capability without bypassing Trust/evidence boundaries.

## Step 8 — Surpass the Reference / Autonomous Operations
Only after Steps 1–7 are grounded do we spend invention budget. OTHRYS-specific target: work can originate from the system itself.

`observe -> detect need/fault -> open Mission -> assign authority -> compose capability -> act/build/repair -> independently verify -> authorize -> deploy/operate -> remember -> continue observing`

Care, Cronos, Titans, Factory, Talos, Trust Canal, Mnemosyne and Mycelium converge here. The operator sees why autonomous work started, current risk/authority, evidence and intervention points.

**Exit proof:** one bounded Oros/OTHRYS condition can create and close a real maintenance Mission without a human initiating a coding chat.

## Priority discipline
Steps are ordered architecture targets, not permission to build eight systems sequentially without evidence. A step may expose already-proven V2 stock quickly; a missing mechanism becomes research/Garden work rather than automatic scope expansion.

The first visible milestone is **OTHRYS OS Alpha**: a coherent Panda-inspired shell over real V2 motor state, with Work/Mission progress as the first deep interaction. Alpha must prefer truthful NOT WIRED states over fake completeness.
