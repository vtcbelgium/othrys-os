# V2-010R Preflight — Block Quarry / Extraction / Compounding

**Great Harvest:** ADAPT, not CREATE.

The repo already contains the proof specimens this mission needs: visit-tracking, image-prep and affiliate-offer were extracted from VTC-style product code with host adapters preserved. V2-010N captured the explicit classification law: `HOST_CONFIG / BRIDGE / CALLER / DEBT / FALSE_POSITIVE`, while the independently reusable algorithm is the extraction target. 010R adds the missing formal `CAPABILITY` class and turns the method into a deterministic Hephaestus tool.

The first implementation should classify declared evidence regions, not scan the world with fuzzy similarity. Input identities and source hashes are frozen by the caller/Harvest. Output is an authority-free extraction assessment with per-region disposition, duplicate capability count, preserved host-glue count, extinction eligibility and explicit rejection reasons.

A candidate may be `EXTRACTION_READY` only when at least one CAPABILITY region exists, every source region is classified, the target Block identity is explicit, and no competing canonical Block implementation is being invented. `EXTINCTION_PROVEN` is stronger: origin duplicate capability count must be zero after the proposed extraction while HOST_CONFIG/BRIDGE/CALLER/DEBT/FALSE_POSITIVE regions remain outside deletion scope.

PandaOS remains UX reference only. Later, a Block candidate can be shown with Panda-like simplicity, but Skills-style convenience never bypasses OTHRYS Block maturity, provenance, qualification or independent proof.
