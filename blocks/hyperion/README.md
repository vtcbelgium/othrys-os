> Authority: subordinate to `FOUNDATION_LAWS.md`, `hyperion/BLOCKS_LIBRARY_DOCTRINE.md`, `BOOK_OF_HYPERION.md`, and normal OTHRYS admission/evidence law.

## Purpose

This domain is the canonical home for future reusable Hyperion Capability Blocks: narrowly scoped commercial-intelligence capabilities that help OTHRYS products get discovered, understood, trusted, activated, retained and — only when financially permitted — monetized.

This is not a marketing-template dump.

A Hyperion Block must still obey:

`ONE BLOCK = ONE CAPABILITY`

and the normal OTHRYS anatomy:

`CONTRACT -> PORTS -> BLOCK DIRECTORY -> MANIFEST/PASSPORT -> EVIDENCE -> ADMISSION`

Nothing in this folder gains runtime authority, maturity or composition rights without explicit qualification.

## Required Hyperion-specific evidence

In addition to normal Block evidence, a commercial-intelligence Block should eventually be able to answer:

- Which contexts is it eligible for?
- Which contexts prohibit it?
- What user job does it support?
- What metric is it trying to improve?
- What trust/friction cost can it introduce?
- How does it behave when confidence is low?
- Is silence a valid output?
- What disclosure is required?
- Does any payout influence recommendation ranking?
- What happens when financial gates are closed?
- How is its effect measured over retention/lifetime value rather than only clicks?
- Can it be removed cleanly without breaking the core user job?
