## Purpose
Colony and node routing across OTHRYS machines.

## Current house law
Mycelium routes work; it does not create mission authority or trust a node by presence alone. Current multichannel planning is three-dimensional only in the routing sense: resource patch x capability x independent work lane. It plans bounded placements but does not launch workers, own leases, or permit shared-path parallel mutation. Current planner supports PACK/SPREAD and strict all-or-nothing variants, cumulative advertised-capacity accounting, and optional saturation-aware scoring; these remain routing policy only. Current V2 also has deterministic WorkKey identity and planning-only Anastomosis: equivalent shareable Claims may map to one producer plan only when both WorkKey and compatibility digest match; Claims never merge and independent-verification Claims never fuse. V2-010M adds authority-free metabolism/calibration: truthful resource dispositions, seven metabolic modes, measured concurrency knees and explicit GROW/HOLD/CONTRACT/QUIESCE planning under the project ceiling. No CAS, producer join, artifact reuse, worker launch, learned legality or execution authority is admitted by these planners.

## Future direction — adaptive trails, complexity must be earned

**Status:** FUTURE IDEA / NOT IMPLEMENTED / NOT AUTHORITY.

Do not force Mycelium into every organ-to-organ call. OTHRYS should preserve simple, explicit typed connections between organs wherever those are sufficient. Mycelium must not become mandatory middleware, a second Switchyard, or a reason to manufacture parallel work.

A promising future role is **adaptive connective tissue** around those direct connections. Real operations can leave compact trail evidence such as: task/work fingerprint, organs/capabilities used, model or Block route, device/resource state, latency/cost/retries, and independent Talos outcome. Frequently successful, recent, efficient trails may strengthen as recommendations; weak, stale, expensive, throttled, or failing trails may weaken. Trail strength is experience, never permission.

Potential future use inside an OTHRYS-native Builder is especially interesting: Mycelium could learn which context, tool, memory, model, repair, and verification paths work best for different engineering tasks while the underlying models remain replaceable Forge engines. This is explicitly **not** a commitment to build our own Builder now.

**Decision law:** complexity must be earned by measured need. Training Mode should first accumulate real jobs and evidence. If direct Hephaestus -> qualified builder -> Talos routing remains optimal, keep it simple. Build learned trail selection or deeper Builder integration only when repeated evidence demonstrates a material advantage.

**Candidate future law:** Mycelium optimizes observed resources and flow; it never creates work merely to optimize it, never grants authority, and never overrides explicit organ contracts, Switchyard legality, or Talos verification.
